Существует 3 вида свойств:
1. properties (именованные свойства данных) - отображают строки в значения, включают методы
2. accessors (именованные свойства с функциями доступа) - специальные методы, вызовы которых выглядят, как свойства чтения или записи. 
3. internal properties (внутренние свойства) - не доступны из js напрямую, записываются в \[\[]], например \[\[Prototype]].

Дескриптор - это метод, который позволяет добавлять или изменять свойства объекта. Дескрипторы бывают 2 основных типов:
1. data descriptor - это свойство, имеющее значение, которое может быть или не быть записываемым. 
  - value - значение свойства
  - writable - указывает, можно ли изменять значение свойства
  - enumerable - указывает, будет ли свойство перечисляться в циклах for..in
  - configurable - указывает, можно ли удалять свойство или изменять его атрибуты
2. accessor descriptor - это свойство, описываемое парой функции, геттером или сеттером:
  - get - функция, которая вызывается при чтении свойства
  - set - функция, которая вызывается при записи свойства
  - enumerable - указывает, будет ли свойство перечисляться в циклах for..in
  - configurable - указывает, можно ли удалять свойство или изменять его атрибуты

Дескриптор может быть чем то одним из этих 2-ух типов, но не может быть одновременно и тем и другим.

Дескрипторы обладают следующими аттрибутами:
  - value - дескриптор данных, значение ассоциированное со свойством, может быть любым js-значением, значение по умолчанию - undefined
  - writable - дескриптор данных, равен true только в том случае, если значение ассоциированное со свойством может быть изменено с помощью оператора присваивания, если использовать define property то по умолчанию будет false, если создавать объект через литерал и задать в нем свойство, то по умолчанию будет true
  - configurable (оба типа дескриптора) - определяет, может ли свойство быть удалено при помощи оператора delete или могут ли его атрибуты быть изменены. Свойство, которое можно удалить и у которого можно изменить атрибуты, называется настраиваемым, в противном случае оно называется ненастраиваемым. если использовать define property и изменить любой аттрибут приведет к ошибке.
  - enumerable (оба типа дескриптора) - равен true только в том случае, если это свойство можно увидеть через перечисление свойств содержащего его объекта, например в цикле for..in. Если использовать define property то по умолчанию будет false, если создавать объект через литерал и задать в нем свойство, то по умолчанию будет true

object.prototype.__noSuchMethod__ - это специальное свойство, которое может быть определено в объекте. Если объект не имеет метода, который был вызван, то вместо выбрасывания ошибки будет вызван метод __noSuchMethod__, если он определен. Этот метод принимает два аргумента: имя метода и массив аргументов, переданных при вызове метода. Позволяет определить функцию, которая будет выполняться при вызове на объекте метода, которого не существует. Функции принимают 2 аргумента: имя метода и массив аргументов, переданных при вызове метода.


```js
var o = {
__noSuchMethod__: function (id, args) {
    console.log("Вызов метода " + id + " с аргументами " + args.join(", "));
};

o.foo(1, 2, 3); // Вызов метода foo с аргументами 1, 2, 3
o.bar(4,5); // Вызов метода bar с аргументами a
o.baz();
//Вывод
//foo(1, 2, 3)
//bar(4,5)
//baz()
```


object.create(proto[, propertiesObject]) - создает новый объект с указанным прототипом и свойствами. По умолчанию writable, configurable и enumerable для всех свойств, добавляемых через propertiesObject, устанавливаются в false. Если proto не является объектом или null, то будет выброшена ошибка typeError. Если proto является null, то создается объект без прототипа. 

Метод keys возвращает массив, содержащий имена всех перечисляемых свойств объекта, переданного объекта в том же порядке в котором они обходились бы циклом for .. in. Разница между циклом for .. in и методом keys заключается в том, что метод keys возвращает только собственные перечисляемые свойства объекта, тогда как цикл for .. in возвращает все перечисляемые свойства, включая унаследованные. 

Чтобы получить все свойства, а не только перечислимые, используется метод getOwnPropertyNames, который возвращает массив, содержащий имена всех собственных свойств объекта, включая неперечисляемые.

Метод propertyIsEnumerable возвращает true, если указанный аргумент является собственным перечисляемым свойством объекта, и false в противном случае. Если объект не имеет свойства с указанным именем, то возвращается false. 

метод object.assign используется для копирования собственных перечисляемых свойств из одного или более источников в целевой объект. После копирования метод возвращает целевой объект. Если целевой объект не является объектом, то будет выброшена ошибка typeError. Если источник не является объектом, то он будет проигнорирован. 

Если свойство является незаписываемым, то typeError, целевой объект не будет изменен. Если свойство является настраиваемым, то оно будет перезаписано. Если свойство является ненастраиваемым и незаписываемым, то оно не будет изменено. 

про lodash даже рассказал и про deepcopy оттуда, как 1 из 3 вариантов клонирования объектов.

При копировании свойство из цепочки прототипов не копируется, а просто создается новое свойство в целевом объекте.

метод Object.freeze(obj) замораживает объект, предотвращая добавление новых свойств и изменение существующих. Метод возвращает замороженный объект. Если obj не является объектом, то будет выброшена ошибка typeError. Если obj уже заморожен, то метод ничего не делает и возвращает obj. Значения, являющимися объектами, всё еще могут быть изменены, если они не заморожены.

Метод Object.seal(obj) запечатывает объект, предотвращая добавление новых свойств и делая все существующие свойства ненастраиваемыми. Значения свойств можно изменять, т.к. они остаются записываемыми, по умолчанию все свойства, добавляемые через литерал объекта, являются настраиваемыми, поэтому после запечатывания объекта они становятся ненастраиваемыми. Метод возвращает запечатанный объект. Если obj не является объектом, то будет выброшена ошибка typeError. Если obj уже запечатан, то метод ничего не делает и возвращает obj. Цепочка прототиопов объекта не затрагивается, но свойство __proto__ так же запечатывается, т.е. становится ненастраиваемым.

Object.is(value1, value2) - определяет, являются ли два значения одинаковыми. Метод возвращает true, если оба аргумента имеют одинаковое значение, и false в противном случае. Метод похож на оператор строгого равенства (===), но имеет некоторые отличия. Например, Object.is(NaN, NaN) возвращает true, в то время как NaN === NaN возвращает false. Также Object.is(+0, -0) возвращает false, в то время как +0 === -0 возвращает true. Для всех остальных случаев Object.is(a, b) возвращает true тогда и только тогда, когда a === b.

Поведение метода Object.is не аналогично поведению оператора ==. Оператор == выполняет преобразование типов обоих операндов если они имеют разный тип перед проверкой на равенство, а метод Object.is не выполняет преобразование типов. Поведение метода Object.is не аналогично поведению оператора ===. Оператор === так же как и == считает числовые значения +0 и -0 равными, значение NaN не равным самому себе.

Метод Object.observe(obj, callback) используется для асинхронного обзора изменений в объекте. Он предоставляет поток изменений в порядке их возникновения. Функция callback вызывается каждый раз пари возникновении изменений в объекте obj с массивом всех изменений в порядке их возникновения.

Функция callback принимает следующие аргументы:
- changes - массив объектов, представляющих 1 изменение. Объекты с изменениями содержат следующие свойства:
  1. name - имя измененного свойства, которое было изменено (для изменений типа "add", "update", "delete", "reconfigure"),
  2. object - изменённый объект,
  3. type - строка, указывающая тип изменения. Возможные значения: "add", "update", "delete"
  4. oldValue - старое значение свойства до изменения (только для типов "update" и "delete")

\[\[prototype]] или \_\_proto__  - резервное хранилище свойств и методов объекта, автоматически используемое при поиске. 

\_\_proto__ 

```js
var foo = {
	x: 10,
	y: 20
};

var foo = {
	x: 10,
	y: 20,
	[[prototype]] : Object.prototype
}
```

почти все объекты в js имеют объекты прототипы от которых наследуют свойства и методы. Все объекты, созданные с помощью литералов имеют один и тот же объект прототип, на который в js скрипте ссылаются Object.prototype. У него нет прототипа, т.е. нет унаследованных свойств. 

```js
Object.prototype = 10; //monkey patching

var a = {}; //create "empty" "hash"

alert(a["x"]); //10, but it's not empty 
alert(a.toString); //function
alert(a.constructor); //function
```

Обезьяний патч - это возможность подмены методов и значений аттрибутов классов скрипта во время его выполнения. Практическое применение техники обезьяних патчей - расширение функционала чужих продуктов (фреймворков, библиотек и т.д.), без непосредественного вмешательства в их код. 

Исключаем свойство, непринадлежащее самому объекту 

```js
var emptyHash = Object.create(null);
console.log(emptyHash.toString); //undefined
```

объект, созданный при помощи `Object.create(null)` не имеет прототипа, а значит в нем нет лишних свойств.

```js
// monkey patching
Object.prototype.bar = 1;

var foo = {moo: 2};
for(var i in foo) {
	console.log(i); //bar, moo
}

for(var i in foo) {
	if(foo.hasOwnProperty(i)) {
		console.log(i); //moo
	}
}
```

Обычный цикл for .. in не делает различия между свойствами объекта и его прототипа, он перебирает всё.

В ES6 в 2015 году появилось ключевое слово class. Функция конструктор запускается - new Car(), остальные методы записываются в Car.prototype. 

```js
class Car {
	constructor(color, model) {
		this.color = color;
		this.model = model;
	}
	accelerate(effort) {
		return console.log("Ускорение", effort);
	}
	brake() {
		return console.log("Торможение", effort);
	}
}
```

При объявлении через класс есть ряд отличий:
  1. Car нельзя вызвать без new - будет ошибка
  2. С точки зрения области видимости ведет себя как let, оно доступно только в текущем блоке и только в коде, который находиться ниже объявления класса.

Методы объявленные в классе имеют ряды особенностей:
  1. метод accelerate является методом, т.е. имеет доступ к super
  2. все методы класса работают в строгом режиме, даже если он не указан
  3. все методы класса не перечислимы, т.е. не будут видны в циклах for..in.

При объявлении методов внутри конструктора на каждый экземпляр будет создаваться новая функция-метод, будет потребляться память и конструктор будет работать медленнее. Такие методы нельзя унаследовать, не вызвав конструктор.

При объявлении метода через прототип у нас будет 1 функция на все экземпляры, включая те, что отнаследовались от нашего объекта, наследоваться будет можно без вызова конструктора и методы не будут собственными для экземпляров.

оператор instanceof проверяет, имеет ли объект в своей цепочке прототипов свойство prototype конструктора.

```js
function A() {};
  // A.prototype = {constructor: A};
var x = new A();

x instanceof A; // true
A.prototype = {};  // теряется цепочка прототипов, которая была у x
x instanceof A; // false
```

свойство \[\[Prototype]] объекта x ссылалась на объект указанный в A.prototype.

В ES5 появился метод create, который создает новый объект и использует свой первый аргумент в качестве протипа этого объекта.

```js

	key2: "value2"

var obj2 = Object.create(obj);
console.log(obj2.key1);
```

в первом случае мы вносим метод в прототип и каждый объект класса Foo будет иметь ссылку на один и тот же метод, во втором случае мы каждый раз при создании нового объекта будем делать копию этого метода, что неэффективно.

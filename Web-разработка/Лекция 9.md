### Basics of HTTP

Стандартные вопросы на гос экзамене или защите диплома: 
какие протоколы есть и какой лучше всего использовать лучше всего для определенной задачи

Виды протоколов:
- HyperText Transfer Protocol (HTTP)
- SSL (Secure Sockets Layer)
- TCP (Transmission Control Protocol)
- IP (Internet Protocol)

В мае 2015 года появился протокол HTTP 2.0, его ключевые особенности:
- Мультиплексирование: позволяет отправлять несколько запросов одновременно по одному соединению, что значительно улучшает производительность.
- Расстановка приоритетов для запросов
- Сжатие заголовков: уменьшает размер заголовков HTTP, что ускоряет передачу данных.
- Серверные пуш-уведомления: позволяет серверу отправлять ресурсы клиенту до того, как он их запросит, что может улучшить время загрузки страницы.
- Загрузка нескольких элементов параллельно посредством одного TCP-соединения

Latency - это время, необходимое пакету чтобы добраться от источника в пункт назначения

ETag - уникальный идентификатор который связан с копией документа, если документ изменяется, то изменяется и ETag. Поэтому более эффективно проверять ETag, чем загружать весь документ, чтобы узнать изменился он или нет. Если клиент хочет проверить совпадает ли документ с определенным ETag то он использует заголовок If-Match или If-None-Match.

HTTP METHODS:
1. GET - запрашивает данные с сервера, не изменяя его состояние.
2. HEAD - передается только строка состояния и раздел заголовков, без тела ответа.  
3. POST - отправляет данные на сервер, изменяя его состояние. Например информацию о клиенте или выгрузки файлов, используя html формы. 
4. PUT - заменяет все цели целевого ресурса на сервере загруженным содержимым.
(Дальше он не рассказывал особо):
5. DELETE - удаляет ресурс на сервере.
6. CONNECT - устанавливает туннель к серверу, обычно используется для SSL-соединений
7. OPTIONS - запрашивает информацию о поддерживаемых методах и возможностях сервера.
8. TRACE - возвращает полученный запрос, что позволяет клиенту видеть, что было изменено или добавлено на пути к серверу.


Status codes:
- 1xx - информационные
- 2xx - успешные
- 3xx - перенаправления
- 4xx - ошибки клиента
- 5xx - ошибки сервера

Cookies:
1. управление сеансом (например, для логины, корзины)
2. персонализация (например, для сохранения настроек пользовательских предпочтений)
3. отслеживание (например, для аналитики и рекламы)

Виды куки:
- Session cookies - Сессионные куки - удаляются после закрытия клиента(браузера), т.е. существуют только во время сеанса пользователя
- Persistent cookies - Постоянные куки - удаляются не с закрытия клиента, а при наступлении определённой даты (аттрибут expires) или после определенного интервала времени (аттрибут max-age)
- Secure cookies - Безопасные куки - отсылаются на сервер только, если запрос выполняется по защищённому протоколу HTTPS или SSL, что обеспечивает безопасность передачи данных

Sharding или сегментирование домена - это рассредоточение вашего сервиса по максимально возможному числу разных хостов. 

HTTP2 отправляет фреймы, все они имеют одинаковое строение: тип, длина, флаги, идентификатор потока и полезная нагрузка. Существует 12 различных типов фреймов, 2 наиболее часто используемых - DATA, HEADERS.

Мультиплексирование потоков - означает что пакеты множества потоков смешаны в рамках одного соединения. Отдельные потоки собираются в 1 а затем разделяются на другой стороне.

Нет необходимости использовать спрайты (sprites), т.е. собирать много маленьких изображений в одно и затем использовать JS или CSS для нарезки частей большого изображения. 

Приоритетизация запросов: каждый поток имеет приоритет, используемый для того, чтобы показать какие потоки считают более важными. 
Server push - если клиент запрашивает ресурс X, а сервер предполагает, что клиент наверняка затем попросит ресурс Z, то отправляя этот ресурс клиенту без просьбы с его стороны.

### REST и SOAP

REST
- Определение: архитектурный стиль для распределённых систем, основанный на ресурсах и стандартных HTTP-методах.
- Принципы: ресурсы идентифицируются URI; представления (JSON, XML, HTML) отделены от ресурса; stateless (сервер не хранит состояние клиента); кэширование; единый интерфейс.
- Практика: используются методы `GET`, `POST`, `PUT`, `PATCH`, `DELETE`; результаты передаются статус-кодами HTTP и обычно в формате JSON.
- Плюсы: простота, лёгкий трафик (JSON), хорошо подходит для веб-приложений, мобильных клиентов и микросервисов.
- Минусы: нет единого стандарта для описания контракта (используют OpenAPI/Swagger), отсутствие встроенных механизмов для транзакций и расширённых корпоративных требований.

SOAP
- Определение: протокол обмена сообщениями, использующий XML и жёстко описываемые контракты (WSDL).
- Структура сообщения: `Envelope`, `Header`, `Body` — операции и типы описываются в WSDL.
- Особенности: поддержка WS-* стандартов (WS-Security, WS-AtomicTransaction, WS-ReliableMessaging и др.), встроенные механизмы безопасности и надёжной доставки.
- Плюсы: строгая типизация и контракт, богатые возможности для корпоративной интеграции (безопасность, транзакции, гарантированная доставка).
- Минусы: тяжеловесность (XML и громоздкие заголовки), большая сложность реализации и отладки.

Когда выбирать
- REST — для лёгких, быстрых и масштабируемых публичных API (SPA, мобильные приложения, микросервисы).
- SOAP — для корпоративных интеграций, где важны строгие контракты, расширенная безопасность и транзакции.

Краткое сравнение
- Формат: REST — обычно JSON (или другой), SOAP — XML.
- Контракт: REST — опционально (OpenAPI), SOAP — обязателен (WSDL).
- Расширенные функции: REST — лёгкость и гибкость, SOAP — встроенные WS-* возможности.

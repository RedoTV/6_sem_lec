# Паттерны проектирования в Android

## 1. MVC — Model-View-Controller

```
Model ←→ Controller ←→ View
```
- **Model** — данные и бизнес-логика
- **View** — отображение (XML-макеты)
- **Controller** — связующее звено (Activity/Fragment)

Проблема в Android: Activity/Fragment выступает одновременно Controller'ом и частично View, что приводит к "толстым" Activity.

## 2. MVP — Model-View-Presenter

```
Model ←→ Presenter ←→ View (Interface)
```
- **Model** — данные и бизнес-логика
- **View** — интерфейс (Activity/Fragment реализует интерфейс View)
- **Presenter** — содержит логику представления, не зависит от Android

```kotlin
// Contract
interface MainContract {
    interface View {
        fun showData(data: String)
        fun showError(message: String)
    }

    interface Presenter {
        fun loadData()
        fun onDestroy()
    }
}

// Presenter
class MainPresenter(
    private val view: MainContract.View,
    private val repository: Repository
) : MainContract.Presenter {

    override fun loadData() {
        val data = repository.getData()
        if (data.isNotEmpty()) {
            view.showData(data)
        } else {
            view.showError("Нет данных")
        }
    }

    override fun onDestroy() {
        // Очистка ресурсов
    }
}

// Activity (View)
class MainActivity : ComponentActivity(), MainContract.View {
    private lateinit var presenter: MainContract.Presenter

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        presenter = MainPresenter(this, Repository())
        presenter.loadData()
    }

    override fun showData(data: String) {
        // Обновление UI
    }

    override fun showError(message: String) {
        // Показ ошибки
    }

    override fun onDestroy() {
        presenter.onDestroy()
        super.onDestroy()
    }
}
```

## 3. MVVM — Model-View-ViewModel (основной паттерн в Android)

```
Model ←→ ViewModel ←→ View
              ↕
          LiveData/StateFlow
```
- **Model** — данные, репозиторий, бизнес-логика
- **ViewModel** — хранит состояние UI, переживает конфигурационные изменения
- **View** — Activity/Fragment/Compose, наблюдает за ViewModel

```kotlin
// Model
data class UiState(
    val users: List<User> = emptyList(),
    val isLoading: Boolean = false,
    val error: String? = null
)

// ViewModel
class UserViewModel(private val repository: UserRepository) : ViewModel() {

    private val _state = MutableStateFlow(UiState())
    val state: StateFlow<UiState> = _state.asStateFlow()

    init {
        loadUsers()
    }

    fun loadUsers() {
        viewModelScope.launch {
            _state.value = _state.value.copy(isLoading = true)
            try {
                val users = repository.getUsers()
                _state.value = _state.value.copy(users = users, isLoading = false)
            } catch (e: Exception) {
                _state.value = _state.value.copy(error = e.message, isLoading = false)
            }
        }
    }

    fun addUser(name: String) {
        viewModelScope.launch {
            repository.addUser(name)
            loadUsers()
        }
    }
}

// View (Compose)
@Composable
fun UserScreen(viewModel: UserViewModel = viewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()

    when {
        state.isLoading -> CircularProgressIndicator()
        state.error != null -> Text("Ошибка: ${state.error}")
        else -> {
            LazyColumn {
                items(state.users) { user ->
                    Text(user.name)
                }
            }
        }
    }
}
```

## 4. Repository Pattern

Единая точка доступа к данным, скрывает источник (БД, сеть, кэш).

```kotlin
class UserRepository(
    private val localDataSource: UserDao,
    private val remoteDataSource: UserApi
) {
    fun getUsersFlow(): Flow<List<User>> = localDataSource.getAllFlow()

    suspend fun refreshUsers() {
        val remote = remoteDataSource.getUsers()
        localDataSource.insertAll(remote)
    }

    suspend fun getUser(id: Int): User? = localDataSource.getById(id)

    suspend fun addUser(user: User) = localDataSource.insert(user)

    suspend fun deleteUser(id: Int) = localDataSource.deleteById(id)
}
```

## 5. Singleton

Гарантирует, что у класса только один экземпляр.

```kotlin
// Kotlin object
object DatabaseProvider {
    @Volatile
    private var INSTANCE: AppDatabase? = null

    fun getDatabase(context: Context): AppDatabase {
        return INSTANCE ?: synchronized(this) {
            val instance = Room.databaseBuilder(
                context.applicationContext,
                AppDatabase::class.java,
                "my_db"
            ).build()
            INSTANCE = instance
            instance
        }
    }
}
```

## 6. Observer (наблюдатель)

Основа реактивного программирования в Android.

```kotlin
// StateFlow
class MyViewModel : ViewModel() {
    private val _data = MutableStateFlow("Начальное значение")
    val data: StateFlow<String> = _data.asStateFlow()

    fun updateData(newValue: String) {
        _data.value = newValue
    }
}

// Compose автоматически подписывается
@Composable
fun MyScreen(viewModel: MyViewModel = viewModel()) {
    val data by viewModel.data.collectAsStateWithLifecycle()
    Text(data)
}
```

## 7. Factory Method

Создание объектов через фабрику.

```kotlin
class ViewModelFactory(
    private val repository: UserRepository
) : ViewModelProvider.Factory {
    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        if (modelClass.isAssignableFrom(UserViewModel::class.java)) {
            @Suppress("UNCHECKED_CAST")
            return UserViewModel(repository) as T
        }
        throw IllegalArgumentException("Unknown ViewModel class")
    }
}
```

## 8. Dependency Injection (Hilt / Dagger)

Внедрение зависимостей вместо ручного создания.

```kotlin
// С Hilt
@HiltAndroidApp
class MyApp : Application()

@AndroidEntryPoint
class MainActivity : ComponentActivity() {
    val viewModel: UserViewModel by viewModels()
}

@Module
@InstallIn(SingletonComponent::class)
object DatabaseModule {
    @Provides
    @Singleton
    fun provideDatabase(app: Application): AppDatabase {
        return Room.databaseBuilder(app, AppDatabase::class.java, "db").build()
    }

    @Provides
    fun provideUserDao(db: AppDatabase): UserDao = db.userDao()
}
```

## Сравнение паттернов

| Паттерн | Связь View-Logic | Тестируемость | Использование |
|---------|------------------|---------------|---------------|
| MVC | Высокая | Низкая | Устарел для Android |
| MVP | Средняя (через интерфейс) | Высокая | Использовался ранее |
| MVVM | Низкая (через наблюдение) | Высокая | **Рекомендуемый** |

## Важные моменты

- **MVVM** — основной паттерн для Android, ViewModel переживает поворот экрана
- **Repository** — скрывает источник данных от ViewModel
- **Observer** — реактивное обновление UI через `StateFlow`/`LiveData`
- **Singleton** — для БД, API-клиентов, общих ресурсов
- В Compose `ViewModel` + `StateFlow` — стандартный подход к управлению состоянием
